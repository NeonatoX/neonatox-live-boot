Boot Flow

This section describes the complete boot sequence from firmware to the final init, using the unified μinit (initramfs/init).

High-Level Flow

Firmware (BIOS/UEFI)
        ↓
GRUB
        ↓
Linux Kernel
        ↓
μinit (/init)              ← detects MODE from cmdline / marker
        ↓
profile library (lib/)     ← live | netinstall | disk | embedded
        ↓
runtime phases (libexec/)  ← 10-… → 99-… in lexical order
        ↓
live / disk   → switch_root → systemd
netinstall    → interactive shell (IP + quick guide)
embedded      → interactive shell on the embedded sysroot

Why GRUB

GRUB is used instead of syslinux primarily for flexibility and modern firmware support. While linux-live traditionally uses syslinux, GRUB is widely available and easier to integrate with EFI systems.

Kernel Responsibilities

The kernel initializes hardware, mounts the initramfs as a temporary root, and executes the /init script. It also parses the kernel command line before handing control to /init.

μinit Responsibilities

/init is a single POSIX script that:

  1. Mounts /proc and /sys and prints the banner.
  2. Reads /proc/cmdline and resolves the boot mode (see below).
  3. Sources the profile library from /lib:
  • live → init-live.sh
  • netinstall → init-live.sh + init-net.sh
  • disk → init-disk.sh
  • embedded → init-embedded.sh
  1. Runs every runtime phase in /libexec/[0-9][0-9]-* in lexical order,

sourcing it with "$MODE" as $1.

  1. Ends by either exec switch_root (live/disk) or run_shell

(netinstall/embedded).

A phase that returns non-zero aborts the boot into emergency_shell.

Mode Detection

MODE is resolved with this precedence (contract P0/P0b):

  1. netinstall=1 on the kernel command line → netinstall (wins over any marker).
  2. /etc/neonatox-mode exists (marker baked into an embedded sysroot) → its content.
  3. root= in any form (/dev/…, UUID=…, PARTUUID=…, LABEL=…), **only

when there is no marker → disk** (classic initramfs behaviour).

  1. Otherwise → live (default).

The full per-mode behaviour is documented in Boot Modes; the internal structure in Initramfs Design.

Profiles at a Glance

Mode Libraries Runtime phases Ends in
live init-common.sh, init-live.sh 10, 20, 30, 40, 60, 99 switch_root → systemd
netinstall init-common.sh, init-live.sh, init-net.sh 10, 20, 50, 60, 99 interactive shell
disk init-common.sh, init-disk.sh 10, 20, 60, 99 switch_root → systemd
embedded init-common.sh, init-embedded.sh 10, 20, 50, 60, 99 interactive shell

Build-Time Counterpart

The initramfs is generated by mkinitramfs (mkinitramfs --profile …), which copies /init, /lib and /libexec, installs the profile's PROFILE_REQUIRES binaries from tools/output, and runs the build-time hooks (pre-binaries, post-binaries, pre-pack, pre-microcode). See HOOKS-AND-PHASES.md for the full contract.
